# AdPilot frontend

Next.js 16 (App Router) + React 19 + Tailwind v4. Screens per `../05_DESIGN.md`.

## Run locally

```bash
cd frontend
npm install
cp .env.local.example .env.local   # point NEXT_PUBLIC_API_BASE_URL at the backend
npm run dev
```

Open http://localhost:3000. The backend (`../backend`) must be running for a real
audit — see `../backend/README.md`.

## Phase 3 status — core screens

| Screen | Route | State |
|---|---|---|
| Landing | `/` | done |
| Upload (drag-drop CSV + sample download) | `/upload` | done |
| Instant audit result (headline + ranked cards + opt-in) | `/audit/[accountId]` | done |
| Budget optimizer / Simulator | — | Phase 8 |

- `/audit/demo` renders the sample-CSV result from a static fixture
  (`lib/fixtures.ts`) — no backend needed. Handy for the demo and offline dev.
- `components/WhatsAppOptIn.tsx` is present per the design but only acknowledges
  on submit; Phase 5 wires it to `POST /api/whatsapp/opt-in`.
- Recharts (in the architecture doc) isn't used yet — the Phase 3 screens are
  numbers and cards. It arrives with the budget optimizer.

## Layout

```
app/
  page.tsx                     Landing
  upload/page.tsx              Upload
  audit/[accountId]/page.tsx   Audit result — server component, calls POST /api/analyze
components/                    RecommendationCard, AuditResult, UploadForm, WhatsAppOptIn
lib/
  api.ts                       fetch wrappers + API_BASE
  types.ts                     mirrors backend/app/schemas.py
  format.ts                    ₹ formatting, severity colour map, jargon-free action labels
  fixtures.ts                  static demo audit (matches backend/tests/test_rules.py)
```

## Copy rules (`../05_DESIGN.md`)

No "CPA / CTR / ROAS / impressions" anywhere a user reads — use "cost per sale",
"click rate", "money spent", "sales", "views". One headline number per screen,
stated first. Severity colour (red / amber / slate) is consistent with the
backend and the WhatsApp messages.

> `AGENTS.md` / `CLAUDE.md` in this folder are regenerated by `next dev` on every
> run (Next 16 behaviour). They're committed so the working tree stays clean.
